# HarnessScope v0.4 Collector SDK + Native Collectors Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship HarnessScope `v0.4.0` with Collector Protocol/SDK v1, a shared collector host model, first-party native macOS/Linux process+file collectors, CLI/Desktop integration, and fail-closed exact-head release publication.

**Architecture:** Add `harnesscope-collector-sdk` for the canonical JSON contract and `harnesscope-collectors` for first-party native collector runtime. Node CLI/Electron host collectors through the same newline-delimited JSON process protocol; Tauri hosts the Rust collector runtime directly and exposes only versioned collector actions to the renderer. Every event is validated, sequence-checked, redacted by the existing core, then persisted through the existing workspace path.

**Tech Stack:** Node.js 22; Rust 1.98.1; Tauri 2.11.5; `serde`/`serde_json`; existing `sysinfo 0.39.6`; `notify = 8.2.0`; `crossbeam-channel = 0.5.15`; `sha2 = 0.10.9`; SQLite/rusqlite; `node:test`; GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-04-harnesscope-v0.4-collector-sdk-native-collectors-design.md`

## Global Constraints

- Product version is exactly `0.4.0`; release tag is exactly `v0.4.0`.
- Collector SDK version is exactly string `"1"`.
- V0.3 workspaces remain readable/writable without destructive migration.
- Existing Node CLI commands, Tauri actions, Electron fallback, Node/Rust parity, redaction-before-persistence, and clean-room exporter remain compatible.
- Collectors never write SQLite directly.
- External collector stdout is untrusted NDJSON; human-readable logs use stderr only.
- External collectors run only by explicit user selection; no auto-discovery/auto-execution.
- No authentication bypass, TLS-pinning bypass, code injection, process-memory scraping, privilege escalation, protected-source extraction, or disabling SIP/Gatekeeper/SELinux/AppArmor/other security controls.
- First-party native file collection is metadata-only; content capture is unsupported in V0.4.
- V0.4 release assets are exactly seven files: Windows Setup EXE, MSI, portable ZIP; macOS DMG, app ZIP; source ZIP; `SHA256SUMS.txt`.
- Linux collector ships as source/CLI runtime only; no Linux desktop release artifact in V0.4.
